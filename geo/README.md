# geo/ — offline gazetteer

These files are generated by `node tools/fetch-geonames.mjs [--cache DIR] [CC ...]`. Nothing is fetched at runtime: the app loads them with `<script src>` from `file://`.

| File | Contents |
|---|---|
| `cities.js` | `AM_GEO.cities`: `name\tasciiname\tCC\tadmin1\tlat\tlon\tpopulation\talt`, sorted by population (desc). Places with population ≥ 1000, coordinates to 3 dp (~110 m). `alt` is up to 8 Latin-script alternate names joined by `|` (original spelling with accents, e.g. `München`). It is filled only for population ≥ 15000 and empty otherwise. |
| `admin1.js` | `AM_GEO.admin1`: `CC.code\tname` |
| `countries.js` | `AM_GEO.countries`: `{iso2, iso3, name, names[], lat, lon, region, zip}`. `lat/lon` is the capital; `names` are lowercase, accent-folded aliases; `zip` is the GeoNames postal regex. It matches the raw postcode before normalisation, so validate the user's input before stripping spaces and dashes. |
| `postal/{CC}.js` | `AM_GEO.postal[CC]`: `zip\tlat\tlon\tplace`. The zip is uppercased with spaces and dashes removed. Duplicates are averaged and keep the first place name. For PT, SG, JP, KR and RO the keys are aggregated to a prefix (see below). |
| `postal/index.js` | `AM_GEO.postalIndex`: `{CC: {rows, kb}}`, listing the countries available for selection in settings. |

`basemap.js` is not generated by this tool.

All non-ASCII characters are written as `\uXXXX` escapes, so the files decode correctly whatever charset the page declares.

## Alternate names

`alt` lists names drawn from the cities1000 `alternatenames` column. Names that are not Latin script are dropped. So are names whose folded form (lowercase, accents stripped, non-alphanumerics collapsed to a space) equals the name, the asciiname, or another alt already kept. "City of …" forms are dropped as well. Remaining names are ordered by the language tags in `alternateNamesV2`:

1. The country's own languages, with preferred names first.
2. en, de, fr, it, es, pt and nl.
3. All other languages.

Historic and colloquial names are not used.

## Aggregated postal files

Five countries are reduced to a zip prefix to keep their files small. Each key averages the coordinates and keeps the most common place name. The app's shorter-prefix fallback finds these keys unchanged.

| Country | Prefix | Rows |
|---|---|---|
| PT | 4 digits | 750 |
| SG | 4 digits | 2,665 |
| JP | 5 digits | 7,361 |
| KR | 3 digits | 452 |
| RO | 4 digits | 828 |

The `AGG` table in the script sets these lengths. AE is not built: its GeoNames data holds address-level codes, and postcodes are not used in the UAE in practice.

## Partial postal coverage

GeoNames provides only part of the postcode for these countries. Truncate the normalised input before looking it up:

- **GB**: outward code only (`SW1A1AA` → `SW1A`), meaning everything except the last 3 characters.
- **CA**: forward sortation area only (`K1A0B1` → `K1A`), the first 3 characters.
- **NL**: the 4-digit part only (`1012AB` → `1012`).

GeoNames has no postal file for **IL** and **SA**, so those two are skipped. Addresses there fall back to city or country lookup.
